One name per line. Ctrl/⌘ + Enter runs the lookup.

Location matches the address DUPR returns (e.g. Granby, CT, US): a 2-letter entry must equal the state code, anything longer is matched inside the city/state text. Comma-separate for several (CT, MA), leave empty for all locations. Only the first 30 same-name hits per name are scanned.

Kept in this browser only (localStorage). Your cookie is sent as x-dupr-cookie and used just for your requests — leave it empty to fall back to the cookie the server is configured with. The API key can also be supplied once in the URL: ?key=… (or ?token=…); it is saved locally and then removed from the address bar.

Cookies — server default or your own

By default every request uses the cookie the server is configured with. If that one is missing or expired, paste your own __Host-dupr_at=eyJ… (or just the JWT) into the field above. It is kept in this browser's localStorage, sent as the x-dupr-cookie header, and used only for your requests — nothing is stored server-side. Press Test cookie to check whichever one is in play; clear the field to fall back to the server default.

  1. Sign in at https://dashboard.dupr.com, open DevTools → Application → Cookies.
  2. Copy the two __Host- cookies whose domain is api.dupr.com: __Host-dupr_at (JWT access token — the important one) and __Host-dupr_rt (refresh token).
  3. Server-side default: paste them as one line into tools/dupr/cookie.txt (git-ignored) — __Host-dupr_at=eyJ…; __Host-dupr_rt=eyJ… — or set DUPR_COOKIE, then restart npm run dupr.

Analytics/payment cookies (_ga, _fbp, __stripe_*, ab.storage.*, media/Facebook cookies…) are ignored. The access token lasts ~30 days; when DUPR rejects it, copy a fresh one.
